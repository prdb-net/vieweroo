# Vieweroo architecture decisions

## Established constraints

The [product vision](VISION.md) sets the following constraints for the implementation.

- **Platform and language.** Vieweroo is a native macOS desktop app written in Swift.
- **Media ownership.** Each library references one or more user-selected folders on local disks or mounted network drives. Media files stay in place. Disconnecting a drive preserves its library entries and viewing data.
- **Catalog and viewing data.** A local database holds file references, metadata, playlists, tags, ratings, favorites, and playback history. Watch history must distinguish segments actually played from time skipped by seeking.
- **Metadata lookup.** Match files against the public PRDB API by hash first, then by title. An unmatched file remains playable. Browsing a matched title uses its studio and performer metadata.
- **App lock.** Optional PIN protection covers launch and manual locking. Locking stops playback and conceals library content in windows and macOS window previews.

## Accepted decisions

### 1. Use AVPlayer for MVP playback

Use Apple's AVPlayer from AVFoundation. We expect most videos in the intended collections to be MP4 files, so MP4 is the primary playback target. Native AirPlay support is a deciding factor because watching library videos on an AirPlay receiver is part of the MVP. Verify playback with representative MP4 files from both local folders and mounted network drives, including playback through an AirPlay receiver.

Start with the file URL for local playback and native AirPlay. When a video route rejects the file, retry on the same player using a short-lived HTTP URL that the receiver can fetch from the Mac. Serve only the selected movie to the local link under a random per-stream path. Support byte ranges for seeking. Preserve the playback session, position, paused or playing state, and loop when changing items, including when the receiver paused playback. Close the listener and active transfers when the user returns to local playback, switches titles, leaves the player or locks the app.

During the recursive scan, import files with an `.mp4`, `.m4v`, or `.mov` extension (case-insensitive) and skip other extensions. If AVPlayer cannot decode an imported file, keep its entry and explain the playback failure. After the MVP, test additional container and codec combinations before extending the import filter.

### 2. Distribute a native Apple Silicon app directly

Use Swift 6 and target macOS 14 or later on Apple Silicon only. Distribute the app as a direct download without Apple notarization. Preserving developer anonymity is a release constraint.

Ship a ZIP containing the Apple Silicon `.app`. Document how to build and test from a fresh checkout. Provide English instructions for installation, first launch of the unnotarized app, and manual updates. Replacing the app must preserve the SQLite catalog and access settings. Automatic updates are outside the MVP.

### 3. Use SwiftUI with targeted AppKit integration

Build the library, search, studio views, and settings in SwiftUI. Embed AVKit's AVPlayerView for playback and use AppKit where native Mac behavior requires it. Keep catalog, scanning, matching, and viewing-history logic in a testable Swift core so those behaviors can be exercised without opening a window.

### 4. Use SQLite with GRDB for local persistence

Store all libraries in one SQLite database on the Mac, including when the video files reside on a network drive. Libraries can reference the same PRDB studio and performer records. The Swift core accesses SQLite through GRDB and can use SQL for queries such as finding the most frequently replayed segments of a video. Open the catalog in WAL mode so reads run alongside scans and other writes. Before pending migrations change an existing catalog, copy it to a `Backups` folder beside it and keep the two most recent copies. Rebuild the indexes of case-insensitive tag and studio names once after each macOS update.

Give each library entry a stable local ID independent of its file path and PRDB match. Correcting a match updates the metadata link and preserves the entry's personal data. In the MVP, two distinct files matched to the same PRDB title retain separate entries.

Scope favorites, ratings, and playback history to the library entry. When the same file appears in two libraries, each entry has its own resume position, playback sessions, and watched intervals. Calculate viewing statistics for each library from its own sessions.

Apply a bulk video edit in one catalog transaction scoped to the active library. Preserve collection order when appending to playlists. Record the previous reaction or newly added memberships per changed entry so Undo reverses the batch. Removing selected videos from Watch History deletes their sessions and intervals in that transaction. Keep the resume position independent. Undo restores the removed sessions alongside any subsequent playback.

Each library owns its tags and playlists. Tags apply to entries in their own library, and a playlist can contain only entries from its library. Each tag has a stable ID and a case-insensitive name unique to the library. Migrate existing assignments in insertion order, using the first spelling as the shared display name. Retain the tag when its last assignment is removed.

Store one cover image per tag or playlist with its source membership and presentation time in the local catalog. For an automatic cover, use the first video with a cached still in tag assignment order or playlist order. Keep the cover when more videos arrive or its source goes offline. Removing its source assignment removes the cover in the same transaction. Use an available still from the remaining assignments. Undoing a batch tag or playlist membership removal restores the original order and cover. Preserve any later playlist additions and user-chosen cover. Deleting selected playlists is a single library-scoped transaction. Read exact frames from the source track in presentation order without starting a playback session.

Read original media in place. The explicit Rename File action changes the filename on disk in its current folder, preserves the extension and updates the existing catalog references across libraries. Reject destination collisions. Commit the new references with a pending-rename record before moving the file. When the catalog opens, complete a rename whose file moved and undo one whose file did not. Before removing a source folder, show the number of entries that would lose their last source in this library. Let the user keep those entries with their personal data or remove both. Preserve every entry still covered by another source folder in the library. Deleting an entire library requires confirmation and removes its entries and personal data. Both operations preserve the files on disk and other libraries' data.

### 5. Catalog files locally before enriching them from PRDB

Queue newly added folders alongside pending scans. Leave a running scan in progress. Opening a library checks whether its source folders are reachable. The user can start a full rescan with **Refresh Library**. Make each discovered file available while the scan continues and resolve its metadata in the background.

Read the local video track in the background after discovery, including available entries from older catalogs. Cache encoded dimensions, codec, frame rate and the identified container in SQLite. Derive the quality label from the cached dimensions, retain the information offline and invalidate it when the file changes.

Use OSHash for MVP file identification and reuse the stored hash for unchanged files. Check the Swift implementation against PRDB's reference files and expected results. Defer perceptual hashing (pHash) until after the MVP.

Apply a unique hash match automatically. If the hash does not identify a title, offer title-search results for the user to confirm, even when the search returns a single candidate. Manual search can combine a title query with PRDB studio and performer IDs. Apply filters on the server before paginating the titles. Preserve a user-confirmed title choice across rescans. Removing a match stores a confirmed choice with a null title and clears the lookup flag. A late identification response must respect that choice. Suggested titles remain available for manual selection.

Attempt to identify the studio for every entry. Use the studio from a matched PRDB title when available. Otherwise, look for an exact studio folder within a selected source or a studio prefix at the start of the filename. Compare case-, accent- and width-insensitively and accept spaces, periods, hyphens and underscores between name parts and before the rest of the release. Multiword and camel-case directory names can appear joined in the filename. A plain single-word prefix also needs an immediately following release date (YY.MM.DD or YYYY.MM.DD) and a further release field. Exclude known generic names such as “Black”, numeric names and names shorter than three characters from path-based matching. Conflicting clues or colliding directory names leave the studio unresolved. A PRDB site hint supplies a name to check by the same rules. The catalog upgrade rechecks stored studio guesses locally, preserving manual selections and linked titles.

Keep custom studio names in a library-owned catalog, including names with no assigned videos. Preserve existing manual names during migration. Treat names from the PRDB directory and cached title or studio metadata as shared, read-only choices. Preserve the PRDB site ID, publishing platform and account handle when available. Use the site ID for creator assignments and resolve older name-only selections to a profile only when the name is unambiguous. Refresh the cached directory even when all videos are already matched. Form OnlyFans and Fansly profile links from the platform key and a valid handle. Match names case-insensitively. Renaming a custom studio updates its directory name and manual assignments in one transaction. Reject collisions with other custom or PRDB names and allow changes in capitalization. Deleting a custom studio clears its manual assignments within that library in the same transaction. Store a manual studio selection on the library entry. It takes precedence over automatic detection across rescans until the user removes the manual studio chip.

Treat an unreachable source folder as offline. Remember the volume that held each source. If the folder now lies on another volume and contains nothing but hidden files, treat it as an unmounted share and keep it offline. If a scan encounters an unreadable subtree, continue through its readable siblings and preserve prior observations in the unreadable area. Mark a file as missing only after checking its location. Only credit a source with files its scanner can reach. A separately selected symbolic link can cover files outside the parent scan. Retain offline and missing entries, personal data, and playlist memberships until the user explicitly removes them.

### 6. Record playback sessions and watched intervals

Record a session once actual playback begins. Only sessions with at least ten seconds of played intervals contribute to viewing history and Watch History or update the resume position. A shorter visit preserves the previous resume position. Pausing and resuming, seeking, looping, or switching to AirPlay keeps the same session.

Store the portions of the video timeline actually played in each session. Pausing closes the current interval. Seeking closes it at the departure time, and the next interval starts where playback resumes. Replaying a section, including through a loop, records another pass. Preserve repeated passes so both viewing duration and frequently replayed sections can be derived.

Rank Watch History by the sum of weighted plays. For each qualifying session, count 80% of the fraction of the movie timeline covered and 20% of watch time divided by the shorter of the movie duration and 30 minutes. Cap each fraction at one. Merge overlapping intervals within a session for coverage and include repeated passes in watch time. Break ties by total watch time. Show the raw play count and watch time on the tile.

Persist the local movie duration when playback begins. Backfill available movies with qualifying history from older catalogs in the background. Until the duration is known, count only the time component using the 30-minute threshold.

### 7. Gate the interface, playback and catalog API with the app lock

When PIN protection is enabled, require the PIN on launch and after manual locking. Locking stops local and AirPlay playback and conceals library content and previews. The PIN is an app access control. The catalog, viewing history, and image cache use ordinary local storage without app-level encryption.

Require the current PIN to change it. To reset a forgotten PIN, require successful local macOS user authentication before accepting a new PIN. Resetting the PIN preserves the catalog. If authentication fails or is canceled, keep the app locked and the existing PIN in place.

The optional [local catalog API](CATALOG_API_IDEA.md) binds to IPv4 loopback only while the app is ready. A dedicated random bearer key in the global settings store authorizes metadata access across all libraries. Turning it off deletes the credential. Leaving the ready state closes the listener and its connections. Address entries by library and stable entry ID. Check the metadata revision and apply each partial edit in a single catalog transaction. Imported poster bytes live in a separate catalog table and load on demand. Local display titles take precedence over PRDB titles and filenames.

### 8. Require a personal PRDB API key and use read-only lookups in the MVP

Validate the user's personal PRDB API key online during setup before enabling library or playback features. Store one validated key for all libraries in an owner-only `Settings.sqlite` beside the catalog. Store the salted PIN verifier in the same database. For a legacy catalog, import both Keychain items in one SQLite transaction before opening any library. Remove the old items after the commit and resume unfinished removals on retry. Inaccessible legacy items keep the catalog closed. Subsequent launches use SQLite. After successful setup, keep the library and player available during network or service outages, including on relaunch. Resume pending lookups when PRDB is reachable. An explicit invalid-key response requires a valid replacement before library use can continue. A timeout or rate limit leaves the previous validation intact. Manual and background lookups share the server’s retry deadline for the same key. If a subscription no longer includes API access, explain how to restore access and keep local browsing and playback available.

For file identification, send the OSHash, file size, and filename without its directory path. Evaluate folder names locally for studio detection. MVP requests look up matches and retrieve metadata. User confirmations and corrections stay local. Submitting confirmed hash-to-title associations to PRDB is planned for after the MVP.

### 9. Open the last library by studio

Open the last-used library in its studio overview. Include an **Unknown Studio** group for entries whose studio has yet to be identified. Resolve collection membership and ordering before applying the visit’s search term and filters. Search video metadata within video collections and studio names, platforms and handles in the studio grid. Within each video quality, studio or tag selection, match any selected value. Require a match in every active group. Use the local video track’s quality tier or Unknown, resolved studio identities and case-insensitive tag names. Count unplayed videos from entries without a counted viewing session. Use the same matching predicate for the sheet preview and the applied results. Keep the search term and filters with the scroll position and selection in browsing history. Remember each collection’s last view in memory during its library session. A direct revisit gets an independent scroll position and history entry. Identify studios by site ID or case-insensitive local name, performers by ID and playlists by ID. Clear collection state with navigation history when locking or changing libraries. Store studio favorites and custom cover frames by library and resolved studio identity. Validate the source entry’s membership when saving a cover and when resolving a changed studio assignment or PRDB identity. Preserve the frame across custom studio renames, unique name-to-site resolution and offline sources. Resetting the cover restores the first member’s poster. Rename and delete custom favorites in the same transaction as their studio. Provide sidebar access to favorites, playlists, and frequently watched videos. A video's detail view lets the user start playback at a frequently replayed segment.

### 10. Generate timeline previews automatically after the initial scan

Use an available PRDB preview image for a video tile, with a locally extracted still as the fallback. Source performer portraits from PRDB. As soon as the initial file scan completes, start generating timestamped thumbnail series for the discovered playable videos in the background. This work runs independently of PRDB lookups and of whether anyone has opened the videos. Cache the series locally for the player's timeline and pointer previews on video posters and keep browsing and playback available while generation runs. After opening the catalog, clean up old preview directories that no library references and abandoned builds. Keep previews for offline sources and protect active generators. Count complete cached sets before reporting progress for available videos. Keep pending previews and generation errors scoped to the active library and clear activity details on lock.

### 11. Share playback controls between the library and a second player window

Use native window full screen so AVPlayer, its active item and the privacy boundary stay together. Switching videos closes the previous playback session and reads the selected entry’s current saved position. All playback uses Cinema controls. A title click or the tile’s Details action opens a trailing overlay sharing the collection’s scroll position, query and filters. Switching the inspected title replaces the selection in place. Use cached frames for pointer previews without opening a player or creating a session.

Cinema Mode presents the shared player edge to edge in the same window. Preserve the native window buttons and the video aspect ratio. Apply the shared full-screen idle timer to the entire Cinema overlay, including recommendations. Temporary fading preserves the saved recommendation visibility. Capture the visible video IDs in display order after applying the collection’s search and filters. Enter at the clicked thumbnail or at the first playable result when starting the collection as a whole. Keep this order for the session, including when playback updates Watch History or a reaction changes filter membership. Refresh video availability and honor catalog deletions and playlist removals. Previous and Next replace the current detail visit and skip missing, offline and known unsupported videos. Returning to the collection, switching libraries or locking ends Cinema Mode. Rank Cinema recommendations with the existing related-video ordering restricted to the captured queue. Persist visibility and preferred count independently in app preferences. Accept counts of 2, 4 or 6 and default to 4. Cap the visible count at 4 below 640 pt of player height. Reapply the preferred count when more space becomes available.

The library and one optional AppKit player window each own a player session. Each session owns its AVPlayer, history recorder and captured Cinema selection. Moving the library session transfers the existing controller and restores the browsing visit. A new title explicitly sent to a display uses the second player slot. Use native full screen with separate Spaces. When displays share a Space and a second player is open, fill each display with a borderless window so both pictures remain visible. Restore its original frame on exit. Scope shortcuts to the active window. Locking, changing libraries and quitting tear down both players. A disconnected display pauses its session and presents it in a regular window on a remaining display.

The [interface guide](DESIGN.md) defines layout, spacing and feedback. Use one transient action notice in the unlocked window. Clear it on a library or access change. Keep form errors, persistent status and destructive confirmations at their point of use.

## MVP acceptance checks

- **Identification.** Use the PRDB SDK's OpenAPI contract for `POST /videos/identify`. A batch contains at most 200 files. Associate each result with its input using the client-supplied `ref`. Test four distinct responses: a unique `OsHash` match links the title, a filename match offers a candidate for confirmation, a site-only result supplies a studio when the path supports it, and an ambiguous result leaves the title unresolved. Verify OSHash against the SDK’s [published OSHash tests](https://github.com/prdb-net/prdb-sdk/blob/bf647a6e2164b3cfcdb74bb37d54d9568f939aee/csharp/tests/Prdb.Hashing.Tests/OsHashTests.cs). The SDK’s `docs/video-hashing-vectors.json` covers perceptual hashing.
- **Library isolation.** Add the same file to two libraries. Rate, tag, and play it in one. After restarting the app, verify that each library retains its own state and that correcting a PRDB match preserves personal data.
- **Rescanning.** Refresh once with a source drive disconnected and once with a file missing from a reachable folder. Verify the distinct availability states and that both entries keep their history and playlist memberships. Repeating the scan must preserve entry identities and manual studio choices.
- **Playback accounting.** Play the first minute, seek to minute ten, and play the next minute twice in a loop. At normal speed the result is one session, three minutes of viewing time, two passes through the repeated minute, and zero viewing time in the skipped span.
- **AirPlay and locking.** On an Apple Silicon Mac, play a representative MP4 from a mounted drive through an AirPlay video receiver. Lock Vieweroo during playback. Verify that local and remote playback stop and that the library stays concealed in application windows and macOS window previews until unlocked. Record the hardware result separately from automated player-state tests.
- **Access and recovery.** Use local PRDB test responses for initial key validation, offline relaunch, and explicit key rejection. Automated tests must run without a personal API key. Test both successful and canceled macOS authentication during PIN recovery.
- **Source removal.** Add a folder and a nested folder as separate sources in one library. Check the affected count, exercise both retention choices, and verify that entries covered by the remaining source survive. Confirm that deleting the library preserves original media and entries in a second library.
- **Import and previews.** Include all three supported extensions, a playable file with an uppercase extension, a file with an unsupported codec, and an excluded extension. Verify that an interrupted scan can resume without duplicate entries. Complete the scan without opening any video and verify that a playable file's preview series is generated and cached automatically.
- **Release and migration.** Follow the documented build and test commands from a fresh checkout. Install the packaged app on Apple Silicon and manually update an existing installation. Verify that the migrated catalog retains libraries, ratings, and viewing history and that the app can still access the stored key.
